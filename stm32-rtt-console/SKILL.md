# RTT через OpenOCD: быстрый канал обмена с прошивкой

Применяй, когда нужно: получать журнал из прошивки **быстрее и надёжнее UART**; иметь **двусторонний**
канал (команды внутрь, ответы наружу); разгрузить UART под прикладной протокол; читать журнал, не
занимая последовательный порт, который нужен другому потребителю.

**Статус в проекте: не используется.** В исходниках нет поддержки RTT, встраивание в прошивку не
делалось. **Но проверено (исследование 17):** RTT работает и **без изменения прошивки** — управляющий
блок можно создать в свободной SRAM инъекцией отладчика, OpenOCD найдёт его по строке `SEGGER RTT`.
Ограничение: без поставщика данных канал пуст — сначала должен быть поднят блок RTT в памяти цели.

## 0. Готовый PoC (если нужно «здесь и сейчас»)

```sh
# Вариант A: пассивный блок — канал наполняет отладчик
python scripts/build_block.py --out build/rtt-block.bin
python scripts/run_poc.py       # инъекция + rtt setup/start/channels + чтение
python scripts/run_live.py      # живой поток: отладчик пишет, сервер читает

# Вариант B: перехват вектора через VTOR — данные пишет ЗАГЛУШКА в SRAM, поток без искажений
python scripts/run_vector_hook.py --vector SysTick --seconds 6

# Вариант C: произвольная функция через аппаратную точку останова (медленно, для редких событий)
python scripts/run_bp_hook.py --symbol <symbol> --seconds 10

# Вариант D: РЕЗУЛЬТАТ функции через подмену lr (тот же класс цены, но даёт возвращаемое значение)
python scripts/run_retval_hook.py --symbol <symbol> --seconds 10
```

**Выбор варианта** (замерено 17.10.2026 на STM32F411, SysTick 1 кГц, ST-Link и OpenOCD 0.12):

| Вариант | Произвольная функция? | Отладчик в цепочке? | Флеш | Измеренная производительность | Искажение времени |
|---|---|---|---|---|---|
| **VTOR + заглушка в SRAM** | нет (только векторы) | **нет** | не трогается | **5205 кадров за 5 с** (~1 кГц) | нет |
| **Свободный таймер + вектор (нативно)** | нет (своё прерывание) | **нет** | не трогается | **~1003 Гц по кадрам** | нет |
| **Аппаратная точка останова (FPB)** | **да** | да | не трогается | **8 попаданий за 10 с** | **104×** |
| **Подмена указателя в RAM** | только где вызов идёт через указатель | нет | не трогается | зависит от прошивки: нужен вызов через указатель в RAM | нет |
| **Перехват возврата (`lr`)** | **да, и отдаёт результат** | да | не трогается | **15 значений за 10 с** | как у точки останова |

Практический вывод: для настоящего потока — VTOR или свободный таймер (отладчик не нужен); для
произвольной функции — только точка останова или перехват возврата, оба вносят искажение времени.

## 1. Команды OpenOCD

RTT в OpenOCD есть с версии 0.11. Порядок принципиален: OpenOCD ищет управляющий блок по строке
`SEGGER RTT` в заданном окне памяти, поэтому блок должен существовать **до** `rtt setup`.

```text
rtt setup <адрес> <размер окна> "SEGGER RTT"   # где искать блок
rtt start                                      # найти блок и начать опрос
rtt channels                                   # каналы и их буферы
rtt server start 19021 0                       # канал 0 -> TCP-порт 19021
rtt stop
```

Готовые обёртки: `scripts/start_openocd.sh` поднимает OpenOCD (GDB 3333, telnet 4444) без RTT,
`scripts/rtt_read.sh` после инъекции блока выполняет команды выше через telnet и читает поток 5 с.
`scripts/rtt_help.sh` печатает справку по командам вашей версии OpenOCD.

## 2. Проверка совместимости (до включения)

| Что проверить | Как |
| --- | --- |
| RTT есть в OpenOCD | `scripts/check_rtt_support.sh`: версия, `help rtt`, справка подкоманд |
| Есть свободный регион SRAM под блок и буферы | карта памяти из `.map`: блок не должен пересекаться со стеком, кучей и `.bss`. По умолчанию — `0x2001E000`, последние 8 КБ SRAM F411 (128 КБ); для другого MCU меняются `build_block.py --address`, константы `BLOCK_ADDRESS`/`RTT_CB` в скриптах и `RTT_ADDR` для `rtt_read.sh` |
| Пробник не занят другим сервером | один ST-Link — один OpenOCD; `start_openocd.sh` останавливает прежний процесс с тем же серийным номером |
| Нужен ли поставщик данных в прошивке | без него канал пуст: данные пишет отладчик (вариант A) или заглушка (B, C, D) |

## 3. Требования к проекту для штатного RTT

Встраивание RTT в прошивку (библиотека SEGGER RTT или своя реализация) требует буферов в RAM и
управляющего блока с известным адресом (символ `_SEGGER_RTT` в ELF); тогда инъекция не нужна и
`rtt setup` указывает на этот адрес. Все скрипты навыка запускаются из корня проекта прошивки и берут
ELF из `build/firmware.elf`.
