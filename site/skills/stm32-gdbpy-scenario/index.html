Как работает stm32-gdbpy-scenario

Один сценарий — один прогон — один проверяемый итог. Python внутри GDB доходит до функции, читает или временно меняет переменную, проверяет наблюдаемую реакцию прошивки и возвращает всё как было. Без фреймворка: нужны GDB с Python, GDB-сервер и Python на хосте. Для коротких действий GDB не нужен вовсе — стоп, старт, сброс и чтение адреса выполняются одной командой, в том числе на удалённом стенде по SSH.

Что важно понимать

Запись — не потреблениеВ примере новый период кадров действует только со следующего запланированного кадра: первый интервал после записи остаётся 100 мс.
Проверять наблюдаемоеКлюч питания — намерение прошивки, работу тракта показывает только трафик.
J-Link пишет точки во FlashБез monitor flash breakpoints = 0 J-Link GDB Server ставит программные точки останова записью во Flash. Запускатель включает это сам.
Сброс и прошивка — вмешательствоЧтение памяти ядро не останавливает, а halt, сброс и запись Flash меняют работу платы. На силовой плате — только после проверки, что стенд тестовый.
Имена, а не числаАдрес переменной и смещение поля устаревают с каждой сборкой. Сценарий читает g_app.stats.errors, а адрес для чтения на ходу считает GDB: &g_app.counter. Смещение — только для шага по массиву или с отметкой разработчика.
DEV_ID — не прошивкаDEV_ID и UID говорят о кристалле. Что на плате та же сборка, что ELF, показывает только сверка образа; verify_image для этого не годится: он исполняет код в ОЗУ цели.
Пробник по USB-адресуST-Link V2 со старой прошивкой отдаёт нечитаемый серийник: --adapter-usb-location 7-1.1.3.
Windows и портыФиксированный порт может попасть в диапазон, зарезервированный системой; запускатель берёт порт, выданный ОС.

Насколько проверено

Проверено на стендах 28–30.10.2026

  • 30.10, версия 1.4.0: сверка образа на F411CE (своя сборка — совпадение, чужая — отказ до сценария), хеш UID в отчёте всех STM32 узла, запуск по отчёту окружения
  • 30.10, версия 1.3.0: опознание шести отладчиков узла (ST-Link V2 с нечитаемым серийником, J-Link с AT32), выбор по DEV_ID и типу; окно работы без остановки на пяти STM32 и AT32
  • BlackPill F411CE локально (Windows) и по SSH: команды, сценарий по адресам, копия Flash, прошивка зонда, сценарий зонда, возврат образа с совпавшим хешем
  • F401CC и Blue Pill F103C8 по SSH: то же
  • Nucleo F030R8 и F429ZI (ST-Link V2 по USB-адресу) по SSH: команды и сценарий по адресам
  • AT32F403A за J-Link по SSH: JLinkExe и OpenOCD, сценарий через J-Link GDB Server и OpenOCD

CI и открытые вопросы

  • CI: пример зонда в Renode и четыре исхода шаблона (PASS, FAIL, ERROR с возвратом, TIMEOUT); правила стиля сценария и отказ запуска при их нарушении
  • нулевое чтение сразу после прошивки (повторилось 30.10 в общем прогоне, не в отдельном) — причина не установлена, готовность проверяется переменной прошивки
  • прошивка AT32 через OpenOCD не проверялась: драйвер Flash не опознал МК
