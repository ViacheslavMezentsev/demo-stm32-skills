# Имена из ELF: как найти идентификатор и обратиться к нему без магических чисел

Навык stm32-gdbpy-scenario, раздел 3.5. Сценарий обращается к данным прошивки **по именам**:
переменная, поле, элемент массива, константа enum. Числовой адрес и смещение поля устаревают с
каждой сборкой и молча читают чужие данные. Проверка: `scripts/check_scenario.py` (правила ниже).

## 1. Исходник и ELF — два источника, нужны оба

| Источник | Что даёт | Чего не даёт |
| :--- | :--- | :--- |
| Исходник | смысл: какое поле что значит, какие значения допустимы, где меняется | что осталось после компиляции: оптимизатор убирает и встраивает переменные, C++ меняет имена |
| ELF (DWARF, таблица символов) | то, что реально собрано и прошито: имена, типы, раскладка, область видимости | смысл и требования |

Порядок: в исходнике найти, **что** читать и какое значение ожидать; в ELF той же сборки
проверить, **как** это имя выглядит для GDB и доступно ли оно. Сценарий пишет имя, GDB считает адрес.

## 2. Инструменты

```sh
# таблица символов: имя, адрес, размер (C++ — с расшифровкой имён)
arm-none-eabi-nm -C -S --size-sort build/app.elf | grep -i counter
# переменные и функции по регулярному выражению, с файлом объявления
arm-none-eabi-gdb-py3 -nx -batch build/app.elf -ex "info variables -n counter" -ex "info functions -n ^app_"
# тип выражения без платы (то же, что проверяет check_scenario.py --elf)
arm-none-eabi-gdb-py3 -nx -batch build/app.elf -ex "whatis g_app.mode" -ex "ptype g_app"
# раскладка со смещениями — чтобы понять структуру, а не чтобы вписать смещение в сценарий
arm-none-eabi-gdb-py3 -nx -batch build/app.elf -ex "ptype/o struct AppState"
# локальные переменные функции и где они живут (регистр, стек, «optimized out»)
arm-none-eabi-gdb-py3 -nx -batch build/app.elf -ex "info scope app_handle_mode"
# обратный вопрос: что лежит по адресу из журнала или дампа
arm-none-eabi-gdb-py3 -nx -batch build/app.elf -ex "info symbol 0x20000104"
```

## 3. Маршруты по видам имён

| Что нужно | Как найти | Как писать в сценарии |
| :--- | :--- | :--- |
| Глобальная переменная | `info variables -n ^name$`, `nm -C` | `read("g_app")`, `write("g_mode", MODE_FAST)` |
| `static` в файле | `info variables name` покажет файл; у C++ в `nm` — `_ZL<длина><имя>` | `read("'app.c'::counter")` при совпадении имён в разных файлах, иначе просто `counter` |
| `static` внутри функции (синглтон) | `info scope func`; в `nm` C++ — `_ZZ…E<имя>` | `read("'func'::instance.field")`; для C++ — `'Ns::Board::instance()'::inst` |
| Локальная (стек, регистр) | `info scope func`; нужна сборка `-Og`/`-O0` | только в её кадре: `reach("func")`, затем `read("local")`. «optimized out» — не обходить смещением от SP: наблюдать глобальное следствие или пересобрать |
| Поле структуры, класса | `ptype obj`, `ptype/o T` | `read("g_app.stats.errors")`, `read("ptr->field")`; поля базового класса и `private` GDB видит по имени |
| Статический член класса | `info variables Class::member` | `read("Ns::Class::member")` |
| Элемент массива | `ptype arr`, `whatis arr` | `read("g_buf[3]")`, длина — `read("sizeof(g_buf) / sizeof(g_buf[0])")` |
| Константа enum | `ptype enum State`, `ptype g_state` | `read("STATE_ACTIVE")`, в C++ — `read("State::Active")`; сравнивать с ней, а не с числом |
| Макрос `#define` | в ELF только при `-g3`: `info macro NAME` | без `-g3` — именованная константа в сценарии с ссылкой на заголовок |
| Обёртка `optional`, `variant` | `ptype obj`: поле хранения и признак значения | признак — проверить, поле хранения — по имени (раздел 3.4 SKILL.md); у `etl::optional` в GDB нет `operator->`, путь — `obj.storage.u.value.field` (раскладка зависит от версии ETL: сверить `ptype obj`) |
| Адрес для чтения на ходу (`read_running`) | — | `int(gdb.parse_and_eval("&g_app.counter"))` — адрес считает GDB из ELF той же сборки |
| Регистр периферии | SVD (`Peripheral.Register`) или дескриптор HAL в прошивке | `read("htim2.Instance->CNT")`, `read("hadc1.Instance->DR")`; без дескриптора — адрес из SVD |
| Регистр периферии на ходу | дескриптор HAL | адрес считать **до** окна, пока ядро остановлено: `int(gdb.parse_and_eval("&hfdcan1.Instance->PSR"))`, затем в окне `read_running(адрес)`; не «база плюс смещение» |
| Регистр ядра (DHCSR, SCB, DWT) | ARMv7-M/ARMv6-M Architecture Reference Manual | именованная константа модуля с источником в комментарии: `DHCSR = 0xE000EDF0  # ARMv7-M ARM C1.6.2` |

## 4. Функции, которых нет в ELF под своим именем

С `-O2`/`-Os` функция бывает встроена в вызывающую или превращена в копию с суффиксом:
`Function "Ns::Cls::send" not defined`, а в `nm -C` — только `Ns::Cls::send(...) [clone .constprop.0]`
или ничего. Точка по имени в такой сборке — лотерея. Порядок:

1. `info functions send`, `nm -C build/app.elf | grep send` — есть ли копия `[clone …]`; точку
   ставить на неё по полному имени из вывода (`break 'Ns::Cls::send(int) [clone .constprop.0]'`);
2. функции нет совсем — событие ловить по следствию: рост счётчика (`wait_counter`), соседний
   невстроенный символ (обработчик, колбэк), изменение переменной;
3. адрес вызова из `disassemble` — только с отметкой `# scenario: allow-address: <причина>`:
   он меняется с каждой сборкой;
4. для отладки логики — сборка `-Og`; итог с `-O2` подтверждается следствием, а не точкой.

## 5. Смещения и адреса числом — когда можно

**Запрещено** без явного разрешения разработчика: числовой адрес объекта прошивки (Flash, ОЗУ),
смещение поля (`(char *)&obj + 12`, `base + 8`), приведение адреса к указателю на тип ради
доступа к полю.

**Разрешено**:

- шаг по массиву или упорядоченному набору: `base + i * sizeof(item)`, `flash + VECTOR_RESET * WORD`
  (таблица векторов — упорядоченный набор слов);
- регистр ядра — именованной константой с источником;
- сценарий без ELF (`assets/address_scenario.py`) — отметка в начале файла
  `# scenario: addresses-allowed: <причина>`;
- раскладка зафиксирована разработчиком (протокол, формат во Flash, обёртка без отладочной
  информации) — отметка в строке или строкой выше: `# scenario: allow-offset: <причина>` или
  `# scenario: allow-address: <причина>`. Причина обязательна: без неё отметка не действует.

## 6. Резолвер имён в проекте

Если проекту нужны адреса вне GDB (запись телеметрии по SWD, внешний регистратор), удобно держать
резолвер: список выражений по именам (`&uwTick`, `&g_app.stats.errors`, регистр `svd:ADC1.DR`)
вычисляется GDB офлайн по ELF и по SVD, результат пишется в JSON вместе с хешем ELF. Правила те же:

- вход резолвера — имена, а не адреса; адреса — его выход;
- JSON привязан к хешу ELF: при другой сборке он недействителен;
- сценарий gdb-py берёт адрес через `parse_and_eval` в своём сеансе, а не из JSON прошлой сборки.

## 7. Проверка сценария

```sh
python scripts/check_scenario.py my_scenario.py --elf build/app.elf
```

| Правило | Уровень | Что ловит |
| :--- | :--- | :--- |
| SC01 | ошибка | адрес во Flash или ОЗУ числом — объект прошивки по адресу вместо имени |
| SC02 | ошибка (в константе — внимание) | адрес регистра периферии числом |
| SC03 | ошибка вне константы | адрес регистра ядра или системной области не вынесен в именованную константу; константа без источника — внимание |
| SC04 | ошибка | смещение: `&obj + N`, `(char *)&obj`, `addr + N`; не ловит `base + i * stride` и отмеченное `allow-offset` |
| SC05 | ошибка | серийник пробника, IP-адрес (кроме 127.x), личный путь в сценарии |
| SC06 | внимание | `sleep` в теле сценария: ожидание по часам хоста |
| SC07 | ошибка / внимание | `write` без `restore`; `set var` мимо `write` |
| SC08 | внимание | `while True` без потолка итераций |
| SC09 | внимание | ожидаемое значение числом в `check` (кроме 0, 1, -1) |
| SC10 | ошибка с GDB, внимание без него | имя не разрешается по ELF; локальная переменная после `reach` её функции — сведения |
| SC11 | внимание | точка останова по номеру строки |
| SC12 | ошибка | итог не пишется в `SCENARIO_RESULT` |
| SC13 | внимание | конструкции Python 3.9+ (`removesuffix`, `match`, `X \| Y` в аннотациях, `dict \| dict`): GDB на узле бывает собран с 3.8 |
| SC14 | внимание | `gdb.Breakpoint` в теле сценария мимо `breakpoint_at()`/`reach()`: точка не снимется при отказе |

Запускатель выполняет ту же проверку до подъёма сервера (`--style strict` по умолчанию): ошибка
правила отменяет прогон, предупреждения печатаются и попадают в `run.json`. С `--elf` запускатель
сверяет имена только по таблице символов; полная сверка через GDB — отдельным вызовом
`check_scenario.py --elf`.
